# Команда — инструмент управления IT-командой

Локальный инструмент тимлида: держит память о людях и подсказывает, с кем сегодня разобраться. Один пользователь, никакого деплоя, никаких интеграций, данные лежат в SQLite-файле рядом.

## Запуск

```bash
npm run install:all   # зависимости корня, сервера и клиента
npm run migrate       # создать/обновить схему
npm run seed          # необязательно: демо-данные за 9 месяцев
npm run dev           # http://localhost:4570
```

Порты 4570 (фронт) и 4571 (API) выбраны намеренно: 3000/3001/5173 на этой машине заняты другими проектами, а коллизия проявляется коварно — `localhost` резолвится в IPv6 и запрос уходит к чужому dev-серверу, пока свой спокойно слушает IPv4.

Прочие команды: `npm test` (тесты домена), `npm run studio` (GUI к базе), `npm run build && npm start` (один процесс раздаёт и API, и собранный фронт).

## Что уже работает — этап 1, цикл 1-1

- **Несколько команд** — переключатель в шапке. Изоляция полная: у каждой команды свои люди, отделы, грейды, атрибуты, категории кармы и настройки сигналов. Новая команда заводится с набором по умолчанию, чтобы не начинать с пустого экрана.
- **Панель лида** — сигналы, сгруппированные **по людям**, а не по типам, максимум 7 карточек. Лид думает «с кем сегодня разобраться», а не «какие бывают типы алертов».
- **Форма 1-1 на две минуты** — договорённости прошлого раза чеклистом, три слайдера с прошлыми значениями и клавишами `1`–`5`, заметки, новые обещания с чипами дат, планирование следующей встречи. Черновик пишется в localStorage, `⌘↵` сохраняет.
- **Экран подготовки** — обратная сторона формы: повестка из незакрытого, заметки прошлой встречи, обещания в обе стороны, тренд настроя.
- **Двусторонние обязательства** — «я обещал» / «он обещал». Просрочка своего обещания всегда критична: доверие к лиду ломается именно здесь.
- **Отпуска** — на время отсутствия часы каденции стоят, алерты по человеку не показываются вовсе.
- **Настрой команды** — средние по трём осям на странице команды, каждое рядом с гистограммой распределения.
- **Календарь отсутствий** — таймлайн на три месяца вперёд по отделам, с подсветкой недель, когда отдел теряет половину состава.
- **Фотографии** — загружаются с карточки человека, обрезаются в квадрат и сжимаются в браузере до отправки. Лежат в `data/photos/`, вне git и вне сборки. Без фото — инициалы на стабильном цвете из имени.
- **FIFA-карточки** — 6 универсальных атрибутов с осями skill/will плюс узкие скиллы по специализации. Оценки хранятся снимками с датой, обоснованием и уровнем уверенности. Тир карточки от грейда, OVR по шкале 39–99, полоса соответствия грейду и топ-3 разрыва до следующего.
- **Смежники** — люди вне команды: PM, PO, лид соседней команды. Получают встречи, обязательства и заметки, но не оценки, грейды, настрой и карму: их не оценивают, с ними договариваются. Их просроченные обещания попадают на панель лида наравне с командными.
- **Блоки заметок** — пять структурированных блоков вместо свободного текста: куда он хочет, что драйвит, что демотивирует, риск ухода, что я ему должен. У каждого своя дата пересмотра и кнопка «всё ещё так». Протухший блок попадает в повестку следующей встречи.
- **Режим показа экрана** — кнопка «шарю экран» в шапке. Вырезание серверное: скрытое не уходит в ответ вообще. Прячутся риск ухода, демотиваторы, замеры настроя, чувствительные заметки и все производные от них сигналы. Включённый режим виден плашкой на всю ширину.
- **Карма** — только плюсы. Виджет на панели лида: отметить любого не уходя с главного экрана, лента с описаниями за 90 дней, фильтры по категориям, самоаудит («ты отметил 25 раз · 11 из 12 человек» и поимённо те, кого не отмечал вовсе). Счётчик `за окно / всего` на карточке человека и в списке команды. Категории редактируются в настройках.

## Решения, которые легко сломать по незнанию

Каждое из них было получено дорого — либо из разбора дизайна, либо в реальном прогоне.

**Даты.** Всё, по чему считается «просрочено» (`due_at`, `happened_at`, `assessed_at`), хранится как `TEXT 'YYYY-MM-DD'`, а арифметика идёт через `Date.UTC` в `domain/dates.ts`. UTC-таймстемп дал бы сдвиг на сутки половину суток по Москве, а алертам нужно доверять безусловно.

**Бэкап делается через `VACUUM INTO`, а не копированием файла.** При журнале WAL свежие транзакции лежат в отдельном `-wal`, и обычный `copyFileSync` забирает только основной файл. Проверка на живой базе показала, что такая «копия» содержала **ноль оценок вместо 220 и вообще ни одной таблицы** — вся схема тоже была в журнале. То есть механизм, защищающий все данные, не защищал ничего. Регрессия закреплена в `db/backup.test.ts`.

**Внешние ключи.** better-sqlite3 не включает их сам. `PRAGMA foreign_keys = ON` стоит в `db/index.ts` и должен стоять на каждом соединении.

**Среднее по команде считается по последнему замеру каждого человека, а не по всем замерам подряд.** Иначе тот, с кем встречаешься раз в неделю, влияет на среднее втрое сильнее того, с кем раз в три недели, и «средняя мотивация команды» начинает зависеть от твоего расписания, а не от команды.

**Рядом со средним всегда стоит распределение.** Команда, где все на тройке, и команда, где половина на пятёрке, а половина на единице, дают одинаковое среднее — но вторая в кризисе. Одна цифра эту разницу стирает.

**Отсутствия правятся и удаляются, и это меняет прошлое.** Отпуск переносят, больничный оказывается короче, дату вводят с опечаткой — а запись останавливает часы каденции, то есть ошибка в дате тихо ломает все алерты по человеку. Удаление отсутствия возвращает те дни в счёт: просрочки соответствующих недель пересчитываются. Никакой «мягкой» пометки здесь нет намеренно — это и есть правильное поведение.

**Смысл календаря отсутствий — пересечения, а не список.** Список отпусков читается и в чате; отрезок, когда из трёх iOS-разработчиков остаётся один, видно только на общей шкале. В окно попадают отсутствия, **пересекающие** его, а не только начинающиеся в нём: отпуск, начавшийся вчера, — ровно то, что нужно видеть сегодня.

**Провалы считаются по дням, а не по неделям.** Неделя как единица отвечает на вопрос «отсутствовал ли кто-нибудь на этой неделе», а нужен ответ на «сколько человек нет в один и тот же день» — это разные числа, и первое всегда больше. Первая версия писала «нет 3 из 6» там, где двое просто попали в один календарный отрезок, не пересёкшись ни одним днём. Границы отрезка теперь конкретные даты, а число — пик одновременно отсутствующих.

**Группировка по специализации внутри отдела, а не по отделу целиком.** Подменяют друг друга те, кто делает одну работу: андроидчик не закроет iOS, сколько бы людей ни было в отделе. Порог провала — половина группы и не меньше двух человек одновременно: один в отпуске это просто отпуск, проблема начинается, когда некому подменить.

**Больничный в режиме показа обобщается до «отсутствия».** Календарь без отсутствий бесполезен, поэтому факт остаётся видимым — но причина это медицинская информация, и она вырезается вместе с примечанием.

**График климата — три отдельных мини-графика, а не три линии в одних осях.** У перегрузки обратный смысл: её рост это «хуже», а рост двух других — «лучше». В общих осях взгляд читает три растущие линии как «всё хорошо», то есть график сообщает обратное правде. У каждой меры своя подпись направления (`↑ лучше` / `↑ хуже`), а стрелка изменения красится по знаку оси, а не по направлению линии.

**У графиков своя палитра, отдельная от палитры важности.** Та подбиралась под крупные заливки и текст; на линии в два пикселя она слишком приглушена — проверка `dataviz/scripts/validate_palette.js` показала, что мотивацию и удовлетворённость не различил бы даже человек с полным цветовосприятием (ΔE 13 при пороге 15). Текущий набор `#63a851 · #4a8cc4 · #d15a3d` проходит все проверки для тёмной темы. Менять цвета серий — только через прогон валидатора.

**У шкалы всегда подписаны границы.** Линия без шкалы нечитаема: падение с 5 до 4 выглядит так же, как с 3 до 1.

**Знак нагрузки.** `workloadPressure`: 5 = перегружен, то есть плохо — в отличие от двух других осей. Все чтения обязаны идти через `domain/climate.ts:toGoodness()`, иначе однажды появится тепловая карта с инвертированной колонкой.

**Позитивные сигналы не лежат в карточках людей.** Внутри красной карточки «день рождения через 4 дня» невидим, а это половина смысла ленты: сплошь красную панель закрывают не читая.

**Фокус в блоке климата уходит на группу, а не на кнопку.** Сфокусированная кнопка срабатывает по пробелу. Пока фокус переходил на кнопку, любой пробел в заметках — если не кликнуть в поле мышью — молча менял соседнюю оценку, и замер выглядел достоверным. Поймано только в живом прогоне.

**Имя файла фотографии генерируется на сервере и никогда не берётся от клиента.** Присланное имя вида `../../data/team.db` записало бы файл мимо папки с фотографиями. Плюс к имени добавляется штамп времени: иначе браузер после замены показывал бы старую картинку из кэша. SVG не принимается — он может нести скрипты.

**Специализация не удаляется, если за ней что-то стоит.** Внешние ключи устроены каскадом: специализация → её компетенции → снимки оценок. Одно удаление молча уничтожило бы всю историю оценок по направлению. Поэтому и отделы, и направления скрываются, а по-настоящему удаляются только пустые; в интерфейсе рядом с каждым видно, сколько людей, компетенций и оценок за ним стоит.

**Атрибуты и ожидания настраиваются, а не зашиты.** Общие атрибуты (с осями для матрицы «может × хочет»), компетенции по специализациям и матрица ожиданий по грейдам редактируются в настройках. Набор по умолчанию заводится только на пустой базе.

**Добавление общего атрибута мгновенно обнуляет OVR всей команды.** Это прямое следствие правила холодного старта: пока оценён не весь набор, общий уровень не считается. Поведение верное, но выглядит как поломка, поэтому предупреждение с точным числом людей стоит в форме до кнопки, а не обнаруживается после.

**Атрибут с оценками не удаляется, а скрывается.** Удаление уничтожило бы снимки — историю роста, ради которой всё затевалось. Скрытый атрибут выпадает из OVR и дельты по грейду, но его прошлые оценки остаются видны в блоке «прошлый опыт»: `buildPersonCard` собирает этот блок по полному списку, включая скрытые.

**Смена грейда не пересчитывает оценки — она предлагает их пересмотреть.** Шкала атрибутов абсолютная: «четвёрка» означает одно и то же у джуна и у сеньора, а относительность живёт в ожиданиях грейда. Автоматический пересчёт (например, деление пополам при повышении) сломал бы сравнение по команде, вписал бы в историю снимки, которых лид не делал, и обрушил бы OVR у человека сразу после промо. Вместо этого на карточке появляется напоминание и режим `/person/:id/reassess`.

**Подтверждение без изменения тоже пишет снимок.** «Пересмотрел и подтверждаю четвёрку» — такое же событие, как «поднял до пяти». Без него снять пометку об устаревании можно было бы только соврав, поменяв цифру.

**Автопереход по атрибутам — только с клавиатуры.** После клика мышью фокус уезжал на следующую строку, и набранное обоснование попадало в её обработчик цифр: фраза «выросла на 2 уровня» молча выставляла соседнему атрибуту двойку. Мышью следующий шаг — дописать обоснование, поэтому клик ведёт в поле текста, а не дальше по списку.

**Неполный OVR — это `??`, а не среднее по оценённому.** Частичный балл уверенно врёт, и по самому числу это не видно. То же правило у соответствия грейду: если что-то из ожидаемого не оценено — `null`, а не заниженный процент, который выглядит как факт.

**Надёжность оценки — сигнал, никогда не математика.** Давность и уровень уверенности рисуют пунктир и чип «устарело», но в OVR не входят. Если число падает само, без единого твоего действия, лид перестаёт доверять всем числам приложения — и уже навсегда.

**Превышение ожидания не считается разрывом.** Иначе сильный в одном и слабый в другом выглядел бы ровно как средний по обоим, и дельта перестала бы отвечать на свой единственный вопрос — чего конкретно не хватает.

**Оценки скрываются режимом показа целиком.** Прятать матрицу Skill × Will и оставлять баллы, из которых она считается, — та же утечка на шаг назад. Карточка при этом помечена флагом `assessmentsHidden`: без него она сообщила бы «оценено 0 из 6», то есть соврала бы.

**В режиме показа опасны производные, а не исходные поля.** Вырезать блок «риск ухода» и оставить алерт с заголовком «Высокий риск ухода» — значит не спрятать ничего. Поэтому `domain/sanitize.ts` перечисляет и источники, и всё, что из них посчиталось: алерты о риске и климате, пункты повестки, замеры настроя. Проверять этот режим нужно **по вкладке Network**, а не глазами по экрану — в этом весь смысл серверной реализации.

**Описания блоков прячутся вместе с содержимым.** Пустой слот «Риск ухода» не только выдавал бы, что риск отслеживается, но и приглашал записать в него текст поверх скрытого — режим защиты стирал бы данные. Плюс сервер отклоняет запись в скрытый блок с кодом 409: интерфейс такие блоки не показывает, но забытая вкладка показывает.

**Флаг режима лежит в базе, а не в памяти процесса.** Перезапуск сервера посреди созвона не должен молча снимать защиту: застрять в безопасном режиме неудобно, случайно из него выпасть — необратимо.

**В журнал карьерных событий пишутся названия, а не идентификаторы.** Запись «грейд 2 → 3» через год не читается, а если грейд переименуют или удалят, id не разрешится ни во что. История хранит то, что было верно на тот момент — тот же принцип, что у категорий кармы.

**Текущая команда берётся только из `repositories/teams.ts:currentTeamId()`.** Это единственная точка, откуда её читают все репозитории. Разнеси её по вызовам — и однажды в одном запросе фильтр забудут, а чужие люди появятся в списке тихо, без всякой ошибки. Специализации при этом принадлежат команде **через отдел**, отдельной колонки у них нет намеренно: две ссылки на команду рано или поздно разошлись бы.

**Переключение команды делает `queryClient.clear()`, а не инвалидацию.** В кэше лежат люди и настройки другой команды; пометить их устаревшими мало — показывать их нельзя ни мгновения.

**Режим показа экрана общий, а не покомандный.** Это состояние твоего экрана прямо сейчас, а не свойство команды: переключился между командами посреди созвона — защита обязана остаться включённой.

**Миграция под команды писалась руками.** SQLite отказывается добавлять колонку с внешним ключом и ненулевым значением по умолчанию, а сгенерированное перестроение `settings` пыталось выбрать `team_id` из таблицы, где его ещё не было. Оба места поправлены в `drizzle/0004`.

**Смежник — признак у человека, а не отдельная сущность.** Вся механика встреч, обязательств и заметок уже завязана на `person_id`; отдельная таблица означала бы дублирование половины схемы или полиморфные ссылки. Поэтому `people.kind` = `member | peer`, а смежники отсекаются там, где оценки бессмысленны: карточки, настрой команды, календарь отсутствий, самоаудит кармы. Правило «давно не отмечал карму» для них тоже выключено — отмечать было и не нужно.

**Риск ухода — перечисление, а не текст.** Он поднимает просрочку 1-1 до критичной и включает отдельный алерт, поэтому произвольная строка молча сломала бы движок. Валидация на сервере отклоняет всё, кроме `низкий|средний|высокий`.

**Подтверждение блока отделено от правки.** «Всё ещё так» обновляет дату пересмотра, не трогая текст. Без этого действия единственным способом снять просрочку было бы сделать вид, что что-то изменилось, — и данные начали бы врать ради зелёного статуса.

**У кармы нет весов, и это решение, а не недоделка.** Категория отвечает «что это было», а не «на сколько баллов». Числовой вес — точность, которой здесь нет, и он неизбежно превратил бы признание в подсчёт очков. Значение записи несёт её описание, поэтому описание обязательно, а вес отсутствует. По той же причине список команды не сортируется по карме: рейтинг сделал бы из инструмента помощи турнирную таблицу.

**Категория записи хранится строкой, а не ссылкой на справочник.** Переименование категории переносит и прошлые записи (иначе история осталась бы под именем, которого нет ни в одном фильтре), а категорию с записями нельзя удалить — только скрыть. Удаление оставило бы часть отметок человека невидимой.

**Показываются обе цифры — за окно и за всё время.** Только «всего» — метрика мёртвая: старожил вечно наверху просто потому, что дольше работает. Только «за 90 дней» — теряется масштаб человека.

**Заглушки алертов только временные.** Ручного «скрыть навсегда» нет: сигнал гаснет, когда меняется факт. Иначе появляется зомби-состояние, которое невозможно отладить.

**Исторические агрегаты не фильтруются по текущему статусу.** «Климат за март» читает замеры как есть — это факты о прошлом. Фильтр `active` применяется только там, где смотрят вперёд: алерты, панель, будущая матрица.

**Тайбрейк по `id` в `current_attribute_values`.** Без него две оценки одной датой возвращаются недетерминированно, и OVR мерцает между перезагрузками страницы.

## Вход и аккаунты

Аккаунт заводится на сервере, регистрации через интернет нет:

```bash
npm --prefix server run user:add -- --email почта --name Имя
```

Пароль спрашивается отдельно и не принимается аргументом — аргументы видны
в списке процессов и остаются в истории оболочки. Первый заведённый аккаунт
забирает команды, оставшиеся от однопользовательской версии.

**Что нужно на публичном хосте:**

- HTTPS обязателен. Кука сессии ставится с `Secure` при `NODE_ENV=production`,
  и без TLS она просто не сохранится.
- Обратный прокси и `trust proxy` — иначе `req.ip` покажет адрес прокси, и
  троттлинг входа посчитает все попытки перебора как одну.
- Папка `data/` не должна раздаваться веб-сервером: там база, фотографии и
  тридцать незашифрованных бэкапов. Шифрование диска — на стороне хоста.

## Структура

```
server/src/
  db/schema.ts        вся схема в одном файле
  domain/             чистые функции: даты, каденция, климат, алерты
  repositories/       единственное место с SQL
  api/                роуты и Zod-валидация
client/src/
  pages/              экраны
  shared/ui/          примитивы, полоса контакта, слайдеры, спарклайн
data/                 team.db, backups/, photos/ — вне git
```

Тесты покрывают только `domain/*` — там живёт продукт, остальное плумбинг.
