# Развёртывание

Приложение целиком живёт в докере. На хост не ставится ни Node, ни
компиляторы, ни веб-сервер — на сервере уже работает Outline, и обновлять
из-под него системные пакеты незачем.

## Что нужно заранее

**Домен, указывающий на сервер.** Не пожелание: кука сессии ставится с
флагом `Secure`, и по голому HTTP браузер её не сохранит — вход будет
выглядеть успешным и тут же возвращать на форму. Сертификат на голый IP не
выдаётся, поэтому нужен либо свой домен, либо бесплатное имя вроде
`что-нибудь.duckdns.org` — Let's Encrypt их обслуживает.

Проверить, что DNS доехал:

```bash
dig +short твой-домен    # должен вернуть IP сервера
```

**Свободные порты 80 и 443.** Outline обычно занимает случайные высокие
порты и не конфликтует, но проверить стоит:

```bash
sudo ss -tlnp | grep -E ':(80|443)\s'   # пусто — значит свободны
docker ps                                # что именно уже крутится
```

## Установка

```bash
git clone <репозиторий> /opt/team-dashboard
cd /opt/team-dashboard

echo 'APP_DOMAIN=твой-домен' > .env

# Том с данными монтируется снаружи, а контейнер работает не от root:
# без этого база не запишется.
mkdir -p data && sudo chown -R 1000:1000 data

docker compose up -d --build
docker compose logs -f caddy    # здесь видно получение сертификата
```

Первая сборка занимает несколько минут: `better-sqlite3` компилируется из
исходников.

## Аккаунты

Регистрации через интернет нет. Аккаунты заводятся на сервере:

```bash
# рабочий аккаунт
docker compose exec app node dist/scripts/add-user.js --email почта --name Имя

# демо с выдуманными данными
docker compose exec app node dist/scripts/seed-demo.js
```

Пароль спрашивается отдельно и не принимается аргументом: аргументы видны в
списке процессов и оседают в истории оболочки.

`seed-demo` можно запускать повторно — он возвращает демо в исходное
состояние вместе с паролем. Пароль демо публичный, так что рано или поздно
в нём кто-нибудь наведёт свой порядок.

## Обновление

С машины разработчика:

```bash
./deploy/push.sh
```

Скрипт исключает `.env` из переноса. Это не мелочь: файл с доменом живёт
только на сервере, и `rsync --delete` без этого исключения стирает его —
после чего Caddy не стартует, потому что не знает, для какого имени брать
сертификат.

Миграции применяются при каждом старте контейнера, они идемпотентны. База
лежит в `./data` вне образа и пересборку переживает.

## О чём стоит помнить

**Файрвол и докер.** Docker пишет правила в iptables напрямую, минуя ufw.
Включённый ufw создаёт ощущение защиты, которой нет, а иногда ломает
докеровскую сеть. Приложение объявлено через `expose`, а не `ports` —
наружу оно смотрит только через Caddy, и опубликованного порта в обход
файрвола у него нет.

**Бэкапы.** В `data/backups/` копятся тридцать незашифрованных снимков базы
с заметками о людях. Веб-сервер их не раздаёт, но на диске они лежат как
есть. Пока внутри только демо-данные, это не срочно; станет срочным в день,
когда появится первый реальный человек.

**Что забрать при переезде:** всю папку `data/` — в ней база, фотографии и
бэкапы. Больше состояния нигде нет.
